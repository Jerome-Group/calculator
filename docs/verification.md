# Verification boundaries

The source inventory, mathematical oracle, rendered application and disconnected runtime establish different facts. A correct engine answer cannot establish that a form represents its inputs correctly, its controls work, or the browser can reopen without its origin.

Start with `pnpm --silent verify --help`, `list --json`, then `show <ID> --json`. The versioned contract is [verification-map.json](verification-map.json). Independent default and choice fixtures live in `tests/fixtures/`; command contracts and evidence checks live in `scripts/verification-*.mjs`. `pnpm --silent verify doctor --suite math --json` reports prerequisites without preparing assets.

`pnpm --silent verify run --group core --json` provides one local/CI entrypoint. It runs the owned checks and build closure; its result explicitly records browser verification as `not-run`. The map declares preparation's possible network use and writes separately from no-fetch mathematical execution. Default fixtures and choice fixtures are independent mathematical expectations, not captured implementation snapshots. Approximate values use finite tolerances; bases and solution families also check dimensions or independent parameters, avoiding sign-sensitive snapshots and incomplete residual-only checks.

`pnpm --silent verify run --group deep-math --json` runs valid/invalid mathematical contracts, the observed-result adapter and failure detectors. `--group regressions` isolates editor, notation, display, graph, worker, result-validation and async-component regressions. These regressions also run once through canonical `pnpm test`, which `core` invokes.

`pnpm --silent verify run --suite math --fixture form.matrix_inverse.default --json` runs one fixture. Omitting `--fixture` runs all mathematics fixtures. The runner records standard output/error and structured results in a temporary evidence directory; `--evidence-dir` chooses a directory. Nothing here writes an account workspace or publishes a deployment.

`pnpm --silent verify prove-detectors --case math.scalar --json` proves a real result assertion fails after replacing the returned matrix, then passes again. `catalogue.mapping` removes an actual form mapping in a disposable source fixture. `evidence.stale` proves the evidence reader rejects a stale revision and wrong artifact hashes. These cases do not establish browser/offline/security mutation coverage. An intentionally thrown exception is a harness check, not a mathematical failure detector.

Browser evidence is separately checked by `pnpm --silent verify browser validate --evidence <manifest.json> --json`. A successful record requires the current Git revision, a digest including dirty tracked/untracked source files, the built offline-manifest digest, the required browser fixture IDs, recorded steps/assertions, and artifact hashes. Missing records, unfinished checks and previous-revision observations cannot certify current readiness. Evidence validation reads recorded observations; it does not operate a browser. Browser files can contain synthetic local observations, so keep evidence outside the public source tree.

Exit codes: `0` pass; `1` assertion/evidence failure; `2` invalid arguments or schema; `3` unavailable prerequisite; `4` harness failure. `pnpm --silent verify … --json` or `node scripts/verify.mjs … --json` produces one JSON envelope on standard output; plain pnpm adds an ELIFECYCLE line on nonzero exits, so automated readers must use either supported form; child logs are artifacts. No `core` success substitutes for the browser, invalid/boundary inputs, account races, mobile interaction, multiple themes or genuine disconnected reopening.

The initial map links every source form and choice option to independent fixtures. Runtime control variants beyond catalogue choices—matrix grid/source selection, virtual keyboard/caret handling, conditional fields, graph tables, notebook/object/recovery controls and state transitions—require separate recorded browser scenarios. Coverage counts alone do not prove those interactions.

`pnpm --silent verify run --suite math-invalid --json` checks 27 independent invalid-input contracts separately from 299 valid default/choice cases. The browser map also requires their observed error outcomes. `createObservedMatcher()` in `tests/verification/observed-matcher.mjs` accepts already observed serialized results, using the same typed assertions without importing or executing calculator code; its limited independent TeX parser rejects unsupported notation. An adapter must retain actual rendered status and semantic labels.

`pnpm --silent verify browser match --evidence DOM-CAPTURES.json --json` independently reviews recorded answers. Input shape: `{ "schemaVersion": 1, "captures": [{ "fixtureId": "form.expand.default", "observed": { "status": "exact", "display": { "type": "math", "latex": "x^3+3x^2+3x+1" }, "detailDisplay": null, "notes": [] } }] }`. Capture these values from semantic rendered DOM, including opened required disclosures. This command never calculates a replacement answer or certifies browser freshness; use the full manifest validator separately.

The existing required CI job `checks` runs the same `core` group after a frozen install, including failure detectors. CI retains its structured manifests and hashed logs as a verification artifact; unavailable artifact upload does not replace or override check results. Browser matching/validation remain explicit commands and never become an automatic source-only browser pass.

`pnpm --silent verify run --suite assets --json` checks local links from the built coverage page against both the offline manifest and built files. The previous Dependency licences link pointed to an absent engine README; checking that licences existed elsewhere did not catch the broken destination. External links and explicit application routes are outside this static-file check. The required browser scenario `help-licences` follows Help and coverage → coverage page → Dependency licences and observes readable bundled notices at `/licenses.txt`. A static target check cannot establish that navigation succeeds; changing the link or its detector requires fresh evidence for the resulting source/build fingerprints.

Full browser manifests require `controls: [{ controlId, status: "pass", scenarioIds: ["graph-table"], actions: ["actual activation"], observations: ["actual visible effect"] }]` for every current static control ID. Scenario links must name passing recorded checks. These source places can expand into several runtime controls: record every exercised variant, including dynamic labels, in the actions/observations. Source enumeration does not establish execution.

Record `mathMatcher: { path, sha256 }` pointing to the JSON output of `browser match`. That report hashes its exact captured DOM artifact and the independent fixture/parser contract. The full gate checks report/capture hashes, unique passing fixture checks and matching capture coverage. The capture wrapper must also record the observed `revision`, `sourceFingerprint`, `buildFingerprint` and `runtime: "production-build"`, matching the manifest. Capture these identities when observations are made; never stamp earlier observations with a newer build. All 326 fixture outcomes remain required; unsupported parsing or unexecuted inputs remain non-pass.

Phone dialogs require `modalBounds` records for `finder`, `settings`, `object`, `notebook`, `nested-math`, `sign-out`: `{ id, status: "pass", runtime: "production-build", finalCascade: true, computedTranslate: "none", rect: { x, y, width, height }, viewport: { width, height }, availableHeight }`. Observe the actual built application after final CSS/editor loading. At phone widths up to 480px, require nonnegative coordinates, positive sizes and every edge within the viewport's keyboard-free available height. Preserve actual bounds, computed CSS and screenshots; an earlier build cannot certify a repaired cascade.

Unavailable physical-input/CDP observations may be disclosed separately as `limitations: [{ id, status: "unsupported", kind: "physical-input" | "cdp-unavailable", reason }]`. These disclosures cannot replace any required fixture, scenario or control. Essential production reload and scoped identity checks still require observed passing evidence. Synthetic contract-mutation tests only test ingestion rules; they are never browser runtime evidence.

The editor additionally requires `keyboard-toolbar-fit` at 320px and 390px, with visible layout/Undo/Redo/Paste target bounds, and `editor.compact-arguments` with actual rich-entry/LaTeX integral, sum, power and fraction results. TeX's unbraced scripts consume one token: `\int_1^02\,\mathrm{d}x` means the integral from 1 to 0 of 2, with result −2. A correct form calculation cannot certify this separate rich-entry path.

Graph resource regressions run under a 128 MB Node heap. The graph expression guard limits cumulative allocation to 10,000 elements per evaluation across five constructors and multiplication outputs, including nested calls; dynamic definitions and shadowed user functions retain their semantics. This graph-local bound does not restrict mathematical engine operation sizes.

Unused vendored controls and their dependency closure were removed to keep installed code aligned with the imported feature set. Verification retains engine pins, offline assets, licences, Sites DB migrations and required framework peers. A frozen install and the shared core checks verify the pruned closure; browser evidence must use its newly built styles and assets.

Volatile recovery uses exact owner-scoped workspace snapshots: navigation/sign-out warn only when the latest state lacks a durable device copy or acknowledged cloud save. The actual Gate callback suite checks Keep working, backup export, explicit Proceed and listener cleanup; sync tests check older acknowledgements, offline drafts, read faults and account isolation. The browser scenario `sync.volatile-leave-guard` separately requires in-app dialog Keep working, an export containing the latest work, and quiet navigation after acknowledgement.

Workspace recovery preflights the exact UTF-8 request envelope against the shared 1,800,000-byte API limit. Automatic merging preserves original recovery data when the combined request would exceed that bound; oversized local work stays available for backup and does not trigger a doomed cloud request. Legacy larger remote data remains readable. Pure envelope tests and actual sync regressions cover these outcomes separately from browser recovery/export.

Sign-out recovery uses the existing accessible in-app Dialog; keyboard/phone users can keep working, export the latest backup or explicitly sign out. Native beforeunload remains a navigation safeguard, but the Codex in-app browser cannot reliably operate that native prompt: disclose it as a CDP limitation, never claim native Cancel passed. In-app sign-out recovery remains a required browser scenario.
