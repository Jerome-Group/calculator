# Why model workspace save ordering

Calculator can lose committed work at account boundaries. Event ordering is the main question, so TLC checks a finite TLA+ state machine. Actual TS callback schedules test the mapping. Neither result proves the entire implementation.

The [upstream create-formal-verification skill](https://raw.githubusercontent.com/cursor/plugins/main/pstack/skills/create-formal-verification-skill/SKILL.md) requires code correspondence, stated bounds, counterexamples, and broken-code checks. The [maintenance skill](https://raw.githubusercontent.com/cursor/plugins/main/pstack/skills/maintain-formal-verification-skill/SKILL.md) treats stale descriptions separately from application bugs. Those requirements led to separate UI and sync snapshots, source hashes, real-source mutations, and retained baseline failures.

The [official TLC guide](https://docs.tlapl.us/using:tlc:start) describes finite-state checking and CLI use. The [1.7.4 release](https://github.com/tlaplus/tlaplus/releases/tag/v1.7.4) supplies the pinned verifier. Its published SHA1 matches the downloaded artifact. The runner pins the artifact's SHA256 and uses Java 21.
