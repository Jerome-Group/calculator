# Guided investigations

## Sub-features

Four authored labs, fresh notebook creation, editable cases and operation steps, run settings, serial computation, comparison, preserved snapshots, observations, cancellation and missing-cell resume. `feature.investigations` owns the journeys. History is the only result collection. The focused domain and real-engine suite is `pnpm --silent verify run --suite investigations --json`. The controlled ownership suite is `investigation-async`. These checks do not operate a browser.

## How to get to it

Open **Investigate**. Each lab card has **Start in a new notebook**. The original notebook stays available. **Edit next run** contains cases, questions, operation choices and **Edit step N inputs**, which opens the existing structured operation editor. Its action is **Save next run step**. **Edit shared objects** opens Objects. Run settings are separate from Calculator settings.

## Drive the real workflow

1. Keep a recognizable result in an ordinary notebook. Launch each lab from its card. Confirm a new notebook, empty history, three cases and three editable steps. Return to the original notebook and verify its contents.
2. Run all nine cells of each lab. Open **Full result and inputs**. Independently check matrix determinants `1, 0, 1/1000`, ranks `2, 1, 2`, and solutions `{(1, 1)}`, `EmptySet`, `{(-998, 1000)}`. `EmptySet` is the engine's real mathematical result. Retain its exact status.
3. In the derivative lab, check the reference `cos(1)`, forward formula `(sin(1+h)-sin(1))/h` and the central tool's actual `h/2` estimate `cos(1)*sin(h/2)/(h/2)`. Its step comparison is a diagnostic, not a rigorous bound. Add a zero-step case and retain the returned mathematical error. Check all path cells independently against `0, 1/2, 2/5`. Unequal paths disprove the limit; agreement does not establish existence. Check binomial tails with independent sums. At `k=15`, inclusive and strict tails are `21700/1048576` and `6196/1048576`. At `k=18`, they are `211/1048576` and `21/1048576`. Preserve numeric status. The normal result is an approximation.
4. Edit a case, an object and a step through visible controls. Run again. Select **Saved investigation run** and verify the earlier requests, objects, settings, statuses and results. Original snapshot inputs remain visible. Save **My observation**, reload and confirm it. Cosmetic labels, definition timestamps and display decimals do not change mathematical freshness. Tagged history does not compare its case bindings against ambient parameter defaults.
5. Put a sufficiently long real computation after a completed cell. Click **Stop**, reload and verify the completed evidence and missing cells. Change the next plan and Objects, then use **Resume N missing calculations**. Only missing cells run, using the original snapshot. Retain separate evidence for a returned mathematical error and worker rejection. Worker rejection creates no result and stops the batch.
6. During pending work, switch notebooks and remove the target run. Try competing graph and object calculations. Verify that work stays with the captured notebook and that removed targets receive nothing. Switch synthetic A to B, then separately A to a new A session, while a real request is pending. Verify no stale entry after completion or unmount. Synthetic fixture identity does not prove native Sites sign-in.
7. Export, inspect, import and restore a recovery copy. Confirm observations, original runs and case references survive in separate notebook copies. Load a legacy v1 backup, including objects without timestamps. Use disposable malformed backups for duplicate ids, cell addresses, missing run/case/step references, mismatched cell requests/settings/case bindings and exceeded cases, steps, runs and string bounds. Failed history and input-envelope preflight must change nothing. Retain an unexpectedly oversized real output and verify the remaining cells stop with the export-and-split notice.
8. Remove a history cell and verify **No saved result**. Resume only that cell. Delete a selected run and verify its tagged history entries disappear together. **Remove plan, keep calculations** strips tags and retains ordinary entries. Separately exercise **Remove plan and its calculations** on disposable work. Clear history, when available, leaves saved run inputs with missing comparisons.
9. At 320px and 390px, use **Comparison case**, run selection, form fields and full result details with keyboard and pointer. Check all five workspace destinations and visible focus. Compare the table on desktop and a narrow panel in both themes. Prepare offline, disconnect, reload and calculate a changed uncached case. Reconnect and observe the save acknowledgement.

## Evidence boundaries

Use the machine map's `investigation.*` scenario IDs and new static control IDs. Keep original failures, semantic DOM, screenshots, actual exported files, save acknowledgements and source/build fingerprints. A comparison badge counts retained results, including mathematical errors. It is never a mathematical proof or cloud-save acknowledgement. Native authentication, physical touch and a second real account remain separate evidence.
