# Workspace model correspondence

The model keeps UI `committed` and `pendingSave` separate from sync `session`. Snapshot integers 0, 1, and 2 mean distinct valid full workspaces. They do not represent notebook revisions. Account `a` owns the single mounted Calculator. Account `b` is a fresh alternate owner. `request` retains an outstanding callback even after `stopSave()` cancels its active request.

The modeled clean initialization path runs `Assign` and `Hydrate` in one synchronous code block, without an intervening await. Keeping them as separate model actions conservatively admits extra interleavings that this code path cannot take. This split does not claim that the code yields between them. Replay any counterexample involving the intermediate state against the actual synchronous block before calling it a product bug.

TLC exhausts all reachable states within one mount, two edits, two owners, one epoch change, one in-flight response plus one queued snapshot, and arbitrary repeated flushes. `SignOut` is enabled only while `~warned`. Its first blocked attempt sets `warned` permanently, so the model excludes later leave attempts even if a subsequent flush makes the work durable. Same-owner initialization is limited to no outstanding draft or dirty device save. Identical clean persistence is a stuttering step. `dirty` models the device dirty marker and prevents a spurious request for that path. Owner `b` has clean remote state. Constants `CheckLease`, `CheckAcknowledgement`, and `CheckResponse` are TRUE in both checked configurations. The model is an abstraction whose correspondence was reviewed manually. There is no refinement proof or TypeScript-to-TLA translation.

The model assumes valid, distinguishable snapshots, successful synchronous storage, one JavaScript execution thread, valid successful responses, and eventual completion only when an `Ack` action is chosen. There is no fairness or liveness claim. It omits storage quotas/corruption, crash durability, multiple tabs, conflicts, retries/timeouts, authentication, server authorization, recovery lineage, workspace limits, and computations.

`CommittedPreserved` observes ordinary `SignOut` in the original mount's generation. Account renewal actions check stale callback guards. They do not establish preservation of unsaved work through arbitrary fresh initialization. Covered hashes name the directly modeled source and callback tools, not every transitive import or installed dependency.

The TS check executes actual source modules and transpiles actual Calculator/Gate components using `tests/component-harness.mjs`. It explicitly renders after the edit so the layout callback has run. It generates every ordering of sign-out with each optional subset of timer and pagehide, eleven schedules. It also checks a standalone pagehide, three epoch transitions, an old acknowledgement after a newer save, and a delayed response after an account switch. An eighteenth schedule commits twice before the timer, checks ordinary sign-out blocks, and invokes Gate's real backup callback to inspect its latest committed content. These schedules are a finite test set, not exhaustive React interleavings.

The fixture begins with real `initializeAccount()` completed before mounting Calculator, then substitutes Gate's redundant initialization with that completed identity. Other Gate callbacks use real sync. JSX children, DOM, clocks, network, and storage are controlled substitutes. Fake fetch deliberately ignores abort so old responses can arrive. The stale-response oracle checks both storage and emitted readiness messages. This does not exercise React reconciliation, a real browser's navigation lifecycle, native prompts, Sites, or D1.

The component harness substitutes unlisted imports with placeholders and supplies no service-worker registration surface. It does not execute engine/offline readiness callbacks. The new computation build and offline status imports therefore do not extend the callback checks to those modules.

Mutation receipts demonstrate five real-source breaks. Removing committed staging permits ordinary sign-out and loses the latest backup content. Removing the pagehide listener leaves `original` after a committed edit. Removing the mount lease overwrites account `b` with `committed-1`. Removing draft equality deletes the newer `committed-2` draft when PUT 1 completes. Replacing the response epoch predicate emits "Saved to your account" into account `b` from account `a`'s response. The clean versions of these checks must pass first. Scratch copies are deleted afterward; red receipts and mutant source hashes remain private in `outputs/`.
